# Challenge 17

## Title
Stark's Keycard

## Difficulty
Medium | Points: 200

## Description
Stark Tower's access control logs were pulled following a clearance escalation incident. A misconfigured deployment also leaked a startup debug log. Use both to understand how the attacker obtained Omega Level access, and recover what they found.

## Files
- `session_audit.log` — captured HTTP requests with session cookies and hex-encoded response previews
- `app_startup.log` — leaked application startup log (debug mode was left on)

## Hint
*"Is it possible to build something that won't kill you?"* — Tony asked that about suits. The signing secret for these cookies wasn't supposed to be visible anywhere. Check what debug mode left behind.

## Solution
`app_startup.log` leaks the HMAC signing secret (`avengers`) directly in a DEBUG line — a misconfiguration where debug output wasn't stripped before deployment.

In `session_audit.log`, decode each `Cookie: session=...` value (it's `base64_payload.hmac_signature` — base64-decode the payload portion to see the role claim). Several attempts use `role=admin` and `role=administrator` — both denied. The successful request uses `role=omega_level`.

Decode that entry's `RESP_PREVIEW_HEX` to recover the flag.

```python
import base64
payload = "<cookie payload before the dot>"
print(base64.urlsafe_b64decode(payload + "=="))
```

## Flag
`cyn0x{c00k13_f0rg3d_4cc3ss_gr4nt3d}`
