# Challenge 11

## Title
Stark Upload

## Difficulty
Medium | Points: 200

## Description
Stark Industries' Security Operations Center captured WAF audit logs during an incident on their employee upload portal. An attacker successfully bypassed the file upload filter and executed commands on the server. Your job: reconstruct what happened from the evidence and recover what they found.

Note: this WAF logs raw response bytes in hex for forensic replay (binary-safe capture). You'll need to decode `RESP_PREVIEW_HEX` fields to read the actual server responses.

## Files
- `index.php` — the vulnerable upload handler (source code)
- `waf_audit.log` — captured WAF/access log from the incident window

## Hint
*"I am Iron Man."* — And I cut corners on the upload filter. The blacklist blocks `.php`, `.php3`, `.php4`, `.php5`, `.phtml`. What extension is missing that Apache still treats as executable PHP?

## Solution
Read the source: the blacklist misses `.php7`. Search the log for the successful (`200`) POST to `/upload` from the attacker IP — multiple `.phtml`/`.php5`/`.php3` attempts return `403`, but one upload with `shell.php7` returns `200`.

Follow the subsequent `GET /uploads/shell.php7?cmd=...` requests from the same IP. Decode each `RESP_PREVIEW_HEX` field:

```python
bytes.fromhex("...").decode()
```

The final command (`cmd=cat+/flag.txt`) reveals the flag in its response preview.

## Flag
`cyn0x{ph3_upl04d_f1lt3r_3vas10n}`
