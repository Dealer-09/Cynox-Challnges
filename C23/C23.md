# Challenge 23

## Title
Wakanda Archives

## Difficulty
Hard | Points: 300

## Description
The Wakanda Digital Archive's document viewer was breached via local file inclusion. Network captures from the incident window are available as nginx access and error logs. Reconstruct how the attacker achieved code execution and recover what they found.

## Files
- `index.php` — vulnerable document viewer (source code)
- `nginx_access.log` — captured access log with hex-encoded response previews
- `nginx_error.log` — captured error log (note what it reveals about a wrong assumption)

## Hint
*"Wakanda Forever."* — But not forever secure. The `error.log` shows someone repeatedly guessing the wrong log path. Check the access log's `Server:` detail to find the right one.

## Solution
`nginx_error.log` shows failed attempts to read `/var/log/apache2/access.log` — the wrong path, since this server runs **nginx**, not Apache (confirmed by the `Server: nginx/1.22.1` line in the access log).

In `nginx_access.log`: an LFI confirmation probe reads `/etc/hostname` successfully; `/etc/passwd` is blocked by the blacklist. A request with a malicious `User-Agent` header (`<?php system($_GET['c']); ?>`) gets logged verbatim by nginx. A subsequent LFI request reads `/var/log/nginx/access.log` itself — causing the poisoned User-Agent line to execute as PHP, with `c=cat+/flag.txt`.

Decode that entry's `RESP_PREVIEW_HEX` to recover the flag.

## Flag
`cyn0x{lf1_l0g_p01s0n_w4k4nd4_f0r3v3r}`
